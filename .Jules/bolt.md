## 2024-03-31 - Bounding React State Caches for Large Payloads
**Learning:** Storing massive data structures (like WebGL chart datasets from `.mat` files) in an unbounded React state cache (e.g., `useState<Record<string, FlightData>>({})`) creates severe memory leaks on the client as the user browses through more files. Garbage collection is unable to free the unused data.
**Action:** Always wrap in-memory React state caches that store large payloads with a bounded eviction policy (like Least Recently Used, LRU) with a strict maximum size to protect the browser's heap limit and prevent the app from freezing or crashing.
## 2024-04-03 - Systematic Optimization Across Multi-Runtime Architectures
**Learning:** In codebases utilizing a multi-runtime architecture (e.g., executing Python directly via `PythonShell` and also as a serverless backend like FastAPI on Vercel), performance optimizations made in one execution path must be systematically mirrored in the other. For example, lazy-loading heavy libraries like `scipy.io` and `numpy` was implemented in the standalone script (`lib/extract_data.py`) but missed in the FastAPI application (`api/index.py`), leaving the serverless deployment vulnerable to massive initialization overhead (~400ms) during cold starts for lightweight endpoints like `/api/files`.
**Action:** Whenever optimizing an execution path in a multi-runtime application, audit all alternative paths (e.g., standalone scripts, API routes, scheduled jobs) to ensure the optimization is consistently applied.
